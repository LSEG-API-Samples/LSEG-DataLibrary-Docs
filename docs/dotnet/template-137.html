Logging

The library utilizes the NLog framework internally to provide flexible and convenient logging capabilities, giving the application developer full control of logging output. NLog supports both a configuration file and a C# API to define logging targets and rules.

The following mechanisms are available, applied in this order of priority:

  1. Programmatically intercept all log output - by utilizing the Log interface, an application lambda expression can be defined to capture all library log messages. This can be useful if an application decides to manage library log messages within their own logging frameworks. This mechanism takes priority over the options below.
  2. Define an NLog configuration - if no programmatic interface has been defined (option 1), the library will use the defined configuration (NLog.config) to determine logging targets and rules.
  3. Default logging - if neither of the options above have been defined, a default logging target and rule applies. By default, all log messages with a log level of LogLevel.Info or higher are sent to a file named RDPLog_<pid>.log.

Log Methods

Log.Level (static property, NLog.LogLevel)
Override the minimum NLog log level for all defined logging rules. Default: LogLevel.Off (uses the default file-based configuration described above).

Log.Output (static property, Action<LogEventInfo, object[]>)
Specify the application lambda expression to manage the log events, intercepting all library log messages.

Usage

using LSEG.Data;

// Increase the logging verbosity to Trace
Log.Level = NLog.LogLevel.Trace;

// Alternatively, intercept all log messages programmatically
Log.Output = (logEvent, args) => Console.WriteLine($"{logEvent.Level}: {logEvent.FormattedMessage}");
