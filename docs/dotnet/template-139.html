Sessions - Definitions and Use Cases

The following page will take you through session creation, configuration and usage.

You will see examples on how to create a default session, a specific desktop or platform session, how to use multiple sessions in a given program and what options each of the session types has. Along the way, you will be introduced to several session related concepts, like session state, session events, several authentication and authorization features and configuration.

The session-layer types described here live in the LSEG.Data.Core namespace. Each concrete session variant (DesktopSession, DesktopDirectSession, PlatformSession) exposes a Definition(...) factory returning a session-specific I…Definition fluent builder; the builder's GetSession() method finalises the request and returns an ISession.

Entry points

The Session class is the generic factory used when the session type is chosen from configuration (JSON file):

Session.Definition(string sessionName = default)
Session.Definition(Stream stream, string resourceName = default)
Session.Definition(JObject config)
Session.Definition(string sessionName, Stream stream, string resourceName = default)
Session.Definition(string sessionName, JObject config)
Define a session request. When sessionName is omitted, the sessions.default entry from the configuration is used. Each overload returns an ISessionDefinition whose GetSession() produces an ISession.

Session.DefaultSession (static property, ISession)
The last session created through any of the Definition(...) factories. Convenient for library-level code that needs an implicit session handle.

Session.StateMsg(State state, string sessionName) (static)
Text message associated with a Session.State code.

For type-specific configuration in code (rather than JSON), use the dedicated factories described on their own pages:

  • DesktopSession — for Eikon / Workspace desktop connections.
  • DesktopDirectSession — for Workspace API Gateway (WAG) connections.
  • PlatformSession — for direct Delivery Platform / RDP connections.

ISession members

ISession is the common interface implemented by every session variant.

Member Kind Description
Session.State Open(CancellationToken cancellationToken = default) method Open the session synchronously. Blocks until authentication and platform-specific resource initialisation complete.
Task<Session.State> OpenAsync(CancellationToken cancellationToken = default) method Open the session asynchronously.
bool Close() method Close all opened resources.
Task<bool> CloseAsync() method Close all opened resources asynchronously.
ISession OnState(Action<Session.State, string, ISession> cb) method Register a callback invoked when the session state changes.
ISession OnEvent(Action<Session.EventCode, JObject, ISession> cb) method Register a callback invoked when a session event is reported.
Session.State OpenState property Current open state of the session.
Session.EventCode LastEventCode property Latest event code reported for the session.
object LastEventMessage property Latest event message payload reported for the session.
Connection.State StreamingState property Current state of the underlying streaming connection.
bool SupportsDataRequests property Whether the session supports RESTful data requests. Notably false for sessions configured only for deployed streaming services.

Session State

Session.State (the LSEG.Data.Core.State enum).

State Description
State.Pending The session is waiting to be opened or closed.
State.Opened The session is open and ready to work.
State.Closed The session is closed.

Session Event Codes

Session.EventCode (LSEG.Data.Core.EventCode).

Event Code Description
EventCode.None EventCode not set.
EventCode.StreamConnected Denotes the connection to the streaming service has been successfully established.
EventCode.StreamDisconnected Denotes the connection to the streaming service is not established.
EventCode.SessionAuthenticationSuccess Denotes the session has successfully authenticated this client.
EventCode.SessionAuthenticationFailed Denotes the session has failed to authenticate this client.
EventCode.StreamAuthenticationSuccess Denotes the stream has successfully authenticated this client.
EventCode.StreamAuthenticationFailed Denotes the stream has failed to authenticate this client.
EventCode.StreamDiscoveryFailed Unable to query the streaming service based on specified location during streaming service discovery.
EventCode.TokenRefreshFailed The request to refresh the access token for the session has failed.
EventCode.TokenRevokeFailed The request to revoke the refresh token failed.
EventCode.RealTimeAccessAllowed Real-time access has been granted to this session.
EventCode.RealTimeAccessDenied Real-time access has been denied for this session.

OAuth 2.0 grant types for platform sessions

PlatformSession authenticates against RDP with an IGrant implementation supplied via OAuthGrantType(IGrant grant).

Grant class Purpose Required setters
GrantPassword Resource-Owner Password Grant. Exchanges a user's credentials for an access token. UserName(string), Password(string), optionally Scope(string)
ClientCredentials Client Credentials Grant. Exchanges a client ID / client secret pair for an access token. ClientID(string), ClientSecret(string), optionally Scope(string)
ClientAssertion Client Credentials Grant with a signed JWT assertion. ClientID(string), one of JWKFilename(string) / JsonWebKey(JObject), optionally Scope(string)

All three grant classes are IDisposable and are typically created inside a using scope.

Examples

Create a session driven by configuration (session type comes from the JSON sessions block):

using (ISession session = Session.Definition().GetSession())
{
    if (session.Open() == Session.State.Opened)
    {
        logger.Info("Created session. Done.");
    }
}

Pick a named session from configuration:

// Desktop Session (name matches the entry under `sessions.desktop.*` in configuration)
using (ISession desktopSession = Session.Definition("desktop").GetSession())
{
    // Open and use session here
}

// Platform Session created explicitly in code
var platformSession = PlatformSession.Definition().GetSession();

Sessions can also be configured by embedding a JSON configuration file in your project. The example below assumes there is an embedded resource at the root level. At runtime the assembly is queried for that resource, which is then passed as a stream to the session Definition() call. When using a custom configuration, several other details will be required as follows:

var resources = Assembly.GetExecutingAssembly().GetManifestResourceNames();
using var resource = Assembly.GetExecutingAssembly().GetManifestResourceStream(resources[0]);

// We need to also specify an ADS (Advanced Distribution Server) host 
var session = PlatformSession.Definition(resource)
                             .Host(GlobalSettings.RTDSHost)
                             .GetSession();

// Alternatively, we can use an OAuth grant
// We recommend using Global Settings to load this information from environment variables and avoid hard-coding

using var grantPassword = new GrantPassword().UserName(GlobalSettings.MachineID)
                                             .Password(GlobalSettings.MachinePasswd);

using (var platformSession = PlatformSession.Definition(resource)
                                            .AppKey(GlobalSettings.AppKey)
                                            .OAuthGrantType(grantPassword)
                                            .TakeSignonControl(true)
                                            .GetSession())
{
    platformSession.OnStreamingEndpoint((api, endpoints, s) => DisplayEndpoints(api, endpoints))
                   .OnState((state, msg, s) => Console.WriteLine($"State: {state}. {msg}"))
                   .OnEvent((eventCode, msg, s) => Console.WriteLine($"Event: {eventCode}. {msg}"));
}

The example below shows how to register and use callbacks for session state and events.

List<Session.EventCode> events = new();
List<Session.State> states = new();

var platformSession = PlatformSession.Definition().GetSession();

var sessionState = platformSession.OnEvent((e, o, s) =>
                                  {
                                      output.WriteLine($"Event: {e} - {o}");
                                      events.Add(e);
                                  }).OnState((state, o, s) =>
                                  {
                                      output.WriteLine($"State: {state} - {o}");
                                      states.Add(state);
                                  }).Open();

var isSessionClosed = platformSession.Close();
